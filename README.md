# Сайт Ксении Погореловой

Одностраничный статический сайт. Для просмотра и публикации не нужны база данных, Node.js на хостинге или сборщик. Сайт пока существует **только локально**: домен `k-projects.art` указан в метаданных, но публикация не выполнена.

## Как посмотреть и изменить

В папке проекта запустите `python3 -m http.server 8000`, затем откройте `http://localhost:8000/`. Для проверки упаковки выполните `node scripts/prepare-site.mjs`: команда проверит наличие страницы и ресурсов и создаст папку `dist/`. Проверка Telegram-ссылки: `node --test tests/*.test.mjs`.

- Тексты и порядок блоков: `index.html`.
- Цвета, отступы и адаптивная вёрстка: `styles.css`.
- Username Telegram и текст черновика: только `config.mjs`. Скрипт `site.mjs` подставляет их во все четыре ссылки.
- Исходное фото оставлено вне Git-копии в `../assets/photos.zip`; на сайт включён уменьшенный `assets/portrait.webp` (42 КБ).
- В `dist/` попадают только файлы для сайта. Исходники тестов и рабочие документы не публикуются.

При отключённом JavaScript тексты и разделы видны; ссылки «Написать в Telegram» переходят к блоку записи. Для заполнения ссылок с текстом черновика нужен JavaScript.

## Перед первой публикацией

1. Убедитесь, что `@OUksenia`, цены, формулировки и портрет согласованы с Ксенией. Для превью ссылки ещё нужен отдельный `og-image.jpg` 1200×630 на основе её фото. Пока файла нет, тег `og:image` отсутствует.
2. Подключите обычный виртуальный **Linux-хостинг с SSH-доступом**. По [справке Рег.ру](https://help.reg.ru/support/hosting/dostupy-i-podklyucheniye-panel-upravleniya-ftp-ssh/rabota-po-ssh-na-virtualnom-hostinge) SSH доступен на их тарифах виртуального хостинга, кроме «Хост-Лайт». Перед использованием workflow проверьте, что выбранный тариф принимает **SSH-ключи** и что на стороне сервера работает `rsync`. Если нет, способ загрузки в workflow потребуется изменить под фактические возможности тарифа.
3. В панели хостинга добавьте `k-projects.art` и узнайте **фактическую** корневую папку сайта, SSH-хост, порт и логин. Проверьте доступ к папке тестовым SSH-подключением; не подставляйте примерные пути или адреса.
4. [Привяжите домен к хостингу](https://help.reg.ru/support/hosting/privyazka-domena-k-hostingu/kak-privyazat-domen-k-hostingu), используя IP или DNS, указанные именно для вашей услуги. До изменений сохраните текущую DNS-зону и не удаляйте записи почты (MX, SPF/DKIM и другие TXT). В панели хостинга подключите сертификат для домена и включите HTTPS.
5. Создайте отдельный SSH-ключ для публикации. **Приватную** часть и проверенный отпечаток хост-ключа храните только в GitHub Actions Secrets; **публичную** часть добавьте в разрешённые ключи аккаунта хостинга. Не записывайте пароли и ключи в репозиторий.

Секреты репозитория для `.github/workflows/deploy.yml`:

| Секрет | Значение из настроек хостинга |
| --- | --- |
| `DEPLOY_HOST` | SSH-хост или IP |
| `DEPLOY_USER` | SSH-логин |
| `DEPLOY_PORT` | SSH-порт |
| `DEPLOY_PATH` | Абсолютный путь к корневой папке **этого** сайта |
| `DEPLOY_SSH_KEY` | Приватный ключ публикации |
| `DEPLOY_KNOWN_HOSTS` | Проверенная запись хост-ключа SSH-сервера |

Workflow запускается только после изменения ветки `main` или вручную. Из рабочей ветки он основной сайт не заменяет. Перед загрузкой проверяет пакет, существование целевой папки и SSH-ключ сервера; `rsync` **не использует `--delete`**, поэтому неизвестные файлы на хостинге не удаляются. Без хостинга, секретов и проверки поддержки SSH-ключей автоматическая публикация не проверена.

## Первая публикация, обновление и откат

После настройки хостинга и секретов проверьте страницу локально, внесите изменения из рабочей ветки в `main` и дождитесь зелёного запуска **Publish static site** в GitHub Actions. Затем откройте `https://k-projects.art/` на телефоне и компьютере, проверьте портрет, шрифты, Telegram-ссылку, HTTPS и отсутствие ошибок загрузки. Только после этой проверки считайте сайт опубликованным.

Обычное обновление: изменить файлы в отдельной ветке → проверить локально → перенести изменения в `main`. Для отката откройте **Actions → Publish static site → Run workflow** и укажите полный SHA предыдущего рабочего коммита из `main` в поле `revision`. Workflow заново загрузит его файлы. Ранее добавленные на сервер файлы не удалятся, поэтому после отката проверьте сайт и, если нужно, разберите остаточные файлы вручную. Сохраните SHA последней рабочей версии до каждого обновления.

## Лицензии и источники

Локальные PT Sans и PT Serif взяты из [Google Fonts](https://github.com/google/fonts); их лицензии находятся в `assets/fonts/OFL-PT-Sans.txt` и `assets/fonts/OFL-PT-Serif.txt`. Формат Telegram-ссылки с черновиком описан в [официальной документации Telegram](https://core.telegram.org/api/links).
